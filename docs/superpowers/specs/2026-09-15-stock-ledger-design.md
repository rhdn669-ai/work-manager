# 재고를 「통 실값」 하나로 — 설계 (2026-09-15)

대표님 「지금 시스템이 헷갈리는 부분이 아직 많은거같은데 좀더 단순화 할 방법을 인터뷰 상세하게 해서 구상해보자」

## 1. 인터뷰로 정한 것

| 물음 | 답 |
|---|---|
| 재고 셈 방식 | **A — 세 갈래(도급·사급·판금) 모두 통에 실제 숫자** |
| 「나감」 열의 뜻 | **품목마다** 그 줄을 *다 채운* 호기 수를 `N SET`, 덜 채운 호기는 `· M대 일부` |
| 재고 화면 | 3탭(사급·도급·판금) **그대로 둔다** |

「안 나간 품목은 SET 표시를 안 올려야 맞다」— 품목마다 실제 가져간 대수를 적는다. v142.9 의 「전부 같은 숫자」는 되돌린다.

## 2. 왜 헷갈렸나

| 지금 | 문제 |
|---|---|
| 도급·판금 남음 = 발주 입고 + 손조정 − 나감 (계산식) · 사급 남음 = 통 실값 | 같은 「남음」인데 머릿속 모델이 둘. 도급만 음수가 생기고, 호기 기록을 잘못 적으면 재고가 같이 틀어진다 |
| 「발주 여유」(발주 입고 − 배정 호기가 가져간 양)가 재고와 따로 있음 | 같은 것을 가리키는 두 숫자 |
| 「나감 N SET」이 갈래마다 다르고(도급 9 · 사급 11) 무엇을 세는지 정의가 없음 | 시작한 호기인지 다 채운 호기인지 불명 |

## 3. 규칙 — 「통은 통, 호기는 호기」

통 하나 = 회사 × 품목 × 갈래. 도급·판금은 `wm.paid_stock`, 사급은 `wm.free_stock`(고객사/우리 것 `ours` 그대로).

| 일 | 통 | 기록(log) |
|---|---|---|
| 발주서 입고 체크 (도급·판금) | `+ 입고 수량` | `in · 발주서 이름` |
| 발주서 입고 취소 | `− 그만큼` (0 밑으로는 안 내려감, 그 사실을 기록) | `in-cancel` |
| 재고 화면 「이번 입고」 | `+ n` | `in · 손` |
| 재고 화면 「수정」 | `= n` | `set · 실물 세어 맞춤` |
| 호기 체크에서 수량 적음 | 통에 **있는 만큼만** `−`, 그만큼 줄에 `fromStock` 기록. 모자란 만큼은 「직접 받음」(통 안 건드림) | `out · 호기` |
| 호기 체크에서 수량 줄임 | `fromStock` 만큼만 `+` (직접 받은 몫은 통으로 안 감) | `back · 호기` |

**남음 = 통 값. 음수 없음.** 통이 비면 호기에는 「직접 받음」으로 적히고, 부족은 부족 집계에 남는다.

이건 대표님이 사급에서 이미 쓰고 계신 규칙 그대로다 (「재고에서 가져온 수량이 아니면 다시 빼도 재고로 채워지면 안 되지」). 도급이 특별했던 이유(발주서와 이어짐)는 「발주 입고 체크 → 통 +」 한 줄로 흡수된다.

### 발주 입고가 어느 회사 통으로 가나

BOM 프로젝트에 **「회사」 칸**을 둔다(프로젝트 4개, 한 번만 고르면 됨). 발주서는 BOM 프로젝트에 직결돼 있으니(`bomProjectId`) 그 회사 통에 넣는다. 회사가 비어 있으면 통에 넣지 않고 입고 화면에 「BOM 프로젝트에 회사를 정해 주세요」 경고.

옛 방식 「현장(siteId) 발주서 합산」은 걷어낸다 — 통이 실값이면 발주서를 다시 셀 일이 없다.

### 「나감」 표기

품목·BOX 줄마다:

```
차단기        9 SET               9대가 다 채움
FERRITE CORE  5 SET               5대만. 나머지 4대는 부족 집계에
SMPS          9 SET · 1대 일부    9대 다 채움 + 1대는 덜 넣음
```

툴팁: 「N개 · 다 채운 M대 · 일부 K대」. 「가능 SET」(남음 ÷ 1대당)은 그대로.

## 4. 바뀌는 곳

| 화면 / 부품 | 지금 | 뒤 |
|---|---|---|
| 도급·판금 재고 「남음」 | 계산식 | 통 값 그대로 |
| 도급·판금 재고 기록 | 손조정만 | 발주 입고·호기 나감·되돌림까지 한 줄로 |
| 부족 집계 「재고」 | 계산식 | 통 값 |
| 호기 체크 (도급·판금 줄) | 통 안 건드림 | 사급과 같은 `syncStock` — 통에서 꺼내고 `fromStock` 기록 |
| 발주서 입고 체크 | 호기 자동 배정만 | **통 + 먼저**, 그 다음 자동 배정은 통에서 꺼내는 방식으로 |
| 「발주 여유」(`spareByItem`, `subscribeReceivedFor`) | 재고·부족 집계·호기 체크·생산현황에서 씀 | 전부 제거 |
| `paidSet.stockUsed` | 배정 취소 때 되돌릴 양 | `fromStock` 이 대신함 → 제거 |
| 서비스 | `freeStockService` · `paidStockService` 둘 | `stockService` 하나 — `subscribeStock(kind, company)` · `receiveStock` · `takeStock` · `givebackStock` · `setStockTo`. 안에서 갈래→표 고름. `ours` 는 사급만 |
| `freeStockSync` | 사급 전용 | `stockSync` — 갈래 무관 |

화면 구조(자재 허브 5탭)는 그대로.

## 5. 이행 — 한 번만 굳히기

도급·판금 통은 지금 「조정치」다. 실값으로 바꾸려면 현재 남음을 한 번 통에 심어야 한다.

- 도급 재고 화면에 **관리자 버튼 「통을 실값으로 굳히기」** (도급·판금 각각). 화면이 이미 계산해 보여 주는 `left` 를 그대로 통 `qty` 로 쓰고(`set · 실값 전환`), 설정 `stockLedger[company][kind] = true` 를 저장한다.
- 플래그가 켜진 회사·갈래만 새 규칙으로 읽는다. 켜지기 전엔 지금 계산식 그대로 → 굳히기 전후 남음이 **같아야** 한다(검증 기준).
- 버튼은 켜지면 사라진다. 2회 배포 뒤(안정 확인) 계산식 코드와 플래그를 걷어낸다.
- 사급은 이미 실값 — 손댈 것 없음.

굳힌 뒤 예전 발주서의 입고를 취소하면 통이 그만큼 줄어야 하는데, 그 발주분은 이미 `left` 에 녹아 있으므로 그대로 `−` 하면 맞다. 0 밑으로 내려가면 0 에서 멈추고 기록에 남긴다.

## 6. 검증

- 단위: `stockSync` 이동 셈(기존 `freeStockSync` 시험 확장 — 갈래 3종), 「나감 SET · 일부」 집계, 발주 입고 → 회사 통 고르기.
- 실측(굳히기 전후): 메티스 도급 47종 남음 동일 · FERRITE CORE `5 SET` 에 부족 집계 4대 · 호기 하나에서 도급 1개 적었다 지우면 통이 정확히 1 갔다 돌아옴.
- 게이트: build · verify:unit · eslint · verify:collections.

## 7. 순서 (배포 단위)

1. **나감 표기** — 품목별 `N SET · M대 일부` 로 되돌림 (바로, 다른 것과 독립)
2. BOM 프로젝트 「회사」 칸 + 발주 입고 체크 → 통 `+` (플래그 뒤에서만 반영)
3. `stockService` 통합 + 호기 체크 `syncStock` 갈래 무관 (플래그 뒤)
4. 굳히기 버튼 + 도급·판금 재고·부족 집계가 통 값을 읽음
5. 「발주 여유」·`stockUsed`·현장 발주서 합산 제거, 계산식 코드 삭제

## 8. 하지 않는 것

- 재고 탭 합치기 (대표님 「3 x」)
- 사급 고객사/우리 것 구조 변경
- BOX별 줄 나눔 변경
